Using Panoptes in a HADES package

This guide takes a HADES package from an ordinary test suite to one package-owned behavior test that runs against every declared live database.

It is the canonical adoption guide for package maintainers.

Adoption steps

  1. Add Panoptes (>= 0.3.0) to Suggests.
  2. Copy and customize the database-platform declaration.
  3. Add a consumer integration test for declaration discovery.
  4. Write one database-neutral package behavior test.
  5. Run a PostgreSQL-first test locally with normalized variables.
  6. Provision one protected GitHub environment per external DBMS.
  7. Copy and customize the pull-request/manual workflow.
  8. Validate the workflow against the declaration.
  9. Roll out the remaining supported platforms and maintain them together.

Core behavior-test shape

config <- Panoptes::readDatabaseTestConfig(package = "MyHadesPackage")
Panoptes::skipIfNoLiveDatabase(config)
Panoptes::withDatabaseTestContext(config, verify = TRUE, {
  resultTable <- context$objectPrefix
  on.exit({
    # Remove package-owned database objects.
  }, add = TRUE)
  # Run package behavior and assert its result.
  Panoptes::requireDatabaseTestConnectionAttempted(context)
})

Panoptes owns validation, environment resolution, connection contexts, temporary resources, compatibility checks, and workflow drift detection. The consumer owns database access, package behavior, assertions, fixtures, and cleanup.

The full guide, including configuration fields, context fields, local driver setup, required secrets, fork safety, CI rollout, troubleshooting, and the maintenance checklist, is in vignettes/using-panoptes.Rmd.

The walkthrough uses a PostgreSQL-first subset before expanding the declaration and workflow together.

DuckDB and SQLite are supported as local file-based platforms and do not require JDBC drivers or external-database matrix rows.
